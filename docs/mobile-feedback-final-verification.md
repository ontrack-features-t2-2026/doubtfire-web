## Security and privacy review

Verified in code/tests:

- feedback uploads have server-side authorization, size/MIME/OOXML validation, safe stored names and
  idempotency; raw file/audio drafts are not placed in durable browser storage;
- notification routes are allow-listed and do not derive behavior from private message content;
- Delete all is current-user scoped and bounded by a positive confirmed id;
- demo scenario data is guarded by environment, exact database, profile and synthetic account and is
  not inserted into normal client entity caches;
- PPI viewer exclusion, privacy threshold and suppressed/rounded states remain enforced;
- additional-email tokens are signed, purpose-scoped, versioned and body-posted after the browser
  scrubs the URL fragment before telemetry; jobs contain ids/version only;
- task submission retry uses a preserved server archive, not a client-supplied path/MIME claim.

Still requiring production/device proof or governance:

- two-account browser verification for draft/notification/profile separation;
- production queue/worker/TeX observability and the production-optimised web build;
- an approved external SMTP provider/sender before the one authorised real delivery test;
- Engagement Passport taxonomy, retention, consent, dispute/audit and external-evidence policy.
