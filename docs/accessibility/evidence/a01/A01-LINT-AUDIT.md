## Deduplication and the ancestor caveat

A source element is identified by **revision + repository-relative file path + UTF-8 byte offset of its opening tag**. Every diagnostic start was checked against the source; the opening tag was scanned through quoted attributes before recording its tag and direct event bindings. The implementation first locates the opening tag in the Unicode source string and then explicitly calculates `len(source[:offset].encode('utf8'))`. These are actual byte offsets, not mislabeled string indices. Diagnostic end ranges are retained but are not used as identities.

Element IDs **E001–E025** are shared with the historical table. The cross-revision mapping was verified by file, within-file element order, tag and identical direct event bindings, not by assuming unchanged line numbers. The unit-task-list wrapper still starts at line 152, but its diagnostic range now ends at line 220 rather than 213. This demonstrates why a diagnostic range is not a stable element identity.

`mouse-events-have-key-events` uses descendant-aware `:has(...)` selectors. One directly bound mouse handler can cause diagnostics on several ancestors; conversely, a descendant focus/blur handler can satisfy an ancestor without proving a usable keyboard path. This is selector ancestry, not several independent source handlers. The August ticket's eight tutor-discussion and ten comments-viewer examples illustrate this risk, but its full JSON and exact SHA were not supplied for independent deduplication. **There are zero mouse diagnostics in both captured main snapshots**, so the present 37-to-25 reduction is entirely the 12 click/focus pairs.

Do not discard every long range as an ancestor duplicate: current `attachment-confirmation-dialog.component.html:1` directly intercepts Enter despite spanning 62 lines. Likewise, `unit-task-editor.component.html:186` directly selects a row and its inner div at line 217 directly stops click propagation. Those two overlapping ranges describe **two different handler-bearing elements**, giving four messages across two elements. Their source observations are documented in `main-elements.csv` and the historical inventory.

## Remaining fix-cost ranking and enforcement order

This is a ranking of the source work on **current main**, not a severity ranking or invented hour estimate. The review stack's zero-result run demonstrates remediation, but its changes still need review.

|                     Cost rank | Rule                           | Distinct main elements | Reason                                                                                                                                                                                                                     |
| ----------------------------: | ------------------------------ | ---------------------: | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
|         1 — already completed | `mouse-events-have-key-events` |                      0 | Already `error` and clean on main; preserve the hover/focus regression tests rather than creating an empty toggle PR.                                                                                                      |
|            2 — low, localized | `label-has-associated-control` |                     11 | Most are group captions or warning prose incorrectly using label markup. The date slider also needs a meaningful name on its actual thumb, so bulk tag replacement alone is insufficient.                                  |
| 3 — substantial behavior work | `click-events-have-key-events` |                     12 | Reply/preview actions can use native buttons, but nested row actions, checkbox menus, draggable step selection and propagation wrappers require structural decisions and keyboard tests.                                   |
| 4 — broadest standalone scope | `interactive-supports-focus`   |                     14 | Shares all 12 click elements and adds a conditional contenteditable editor plus an Enter-canceling dialog wrapper. Correct focus behavior must preserve recording/disabled states and avoid meaningless wrapper tab stops. |

**Recommended order:** retain the already-enabled mouse rule, then enable **label → click → focus**, one permanent rule transition per PR. Fix an individual control's semantics atomically; the click PR will naturally clear many focus findings. Focus therefore has a lower marginal cost after click remediation than its standalone scope suggests. One enforcement rule per PR keeps residual counts, regression responsibility and review dependencies clear without splitting a control into an unusable intermediate design.
